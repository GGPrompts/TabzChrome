# Chrome API compatibility evidence

Official documentation was refreshed during the catch-up work using the Google Developer Knowledge corpus and the Chrome DevTools Protocol reference. This is static compatibility evidence, not proof of a loaded browser run.

- [`sidePanel.setPanelBehavior`](https://developer.chrome.com/docs/extensions/reference/api/sidePanel#type-PanelBehavior) defines `openPanelOnActionClick` as a toolbar toggle. Chrome can own that behavior on the existing minimum-116 baseline. Explicit `sidePanel.close` needs Chrome 141 and panel lifecycle events need newer Chrome; importing a manual open/close state machine would unnecessarily raise that baseline. Existing explicit user-gesture opens remain separate.
- [`chrome.debugger` restricted domains](https://developer.chrome.com/docs/extensions/reference/api/debugger#restricted-domains) include Network and Emulation, but not Browser. A page-level geolocation override must not claim that it granted browser/site permission.
- [`Network.emulateNetworkConditionsByRule`](https://chromedevtools.github.io/devtools-protocol/tot/Network/#method-emulateNetworkConditionsByRule) configures request throttling; [`Network.overrideNetworkState`](https://chromedevtools.github.io/devtools-protocol/tot/Network/#method-overrideNetworkState) controls the corresponding navigator state. Both are experimental, so unsupported-method fallback remains necessary. The current protocol lists a top-level `offline` boolean on the rule call even though it is deprecated in favor of newer rule fields. Clear must explicitly remove rules and reset navigator state.
- [`Emulation.setGeolocationOverride`](https://chromedevtools.github.io/devtools-protocol/tot/Emulation/#method-setGeolocationOverride) overrides position or unavailability. Permission must be observed separately and policy/refusal errors reported honestly. A successful CDP command alone does not prove that page JavaScript can obtain the location.
- [`webNavigation`](https://developer.chrome.com/docs/extensions/reference/api/webNavigation) supplies document identity/lifecycle metadata from Chrome 106. Tabz already uses [`sidePanel.open`, introduced in Chrome 116](https://developer.chrome.com/blog/chrome-116-beta-whats-new-for-extensions), so the manifest's combined baseline is 116. The extension name, key and identity are retained.

Search/full-document logs are `/tmp/tabz-execute/chrome-toggle-docs.log`, `chrome-emulation-docs.log`, `chrome-settings-full-docs.log`, and the earlier `chrome-version-*` logs. Protocol documentation describes current interfaces; mocked tests and explicit unsupported-method handling cover compatibility branches without claiming a Chrome-version matrix was run.
